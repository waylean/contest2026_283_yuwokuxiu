# 技术决策：参赛主线采用原生加速度算法

## 结论

参赛版本继续以小米手环 10 Pro 独立版为基准，只使用 openvela 快应用在手环上
可直接获得的系统能力。AstroBox 诊断插件和分片导出链路不作为作品功能、演示内容
或提交附件。

## 原因

1. 在非球场环境按标签执行动作，只能验证接口和程序稳定性，不能替代带击球结果、
   现场动作类型和人工复核的真实羽毛球标注。
2. AstroBox 是研发和侧载工具，不是运动过程中独立运行的作品能力。把它作为核心
   证据会模糊 openvela 原生应用边界。
3. 无权威标注时继续调节阈值容易形成过拟合，无法诚实证明对不同用户、佩戴方式和
   实战动作有效。

## 保留的证据

相关 AI Coding 日志保留，因为它真实记录了方案探索、风险识别和放弃决策。日志不
等同于最终作品能力，提交材料不得把已放弃的诊断链路描述为产品功能。

## 后续算法路线

- 使用有明确物理含义的多证据门控，不以单一加速度峰值判定挥拍；
- 根据静止噪声和采样间隔生成有上下界的自适应阈值；
- 利用相邻事件的方向关系区分击球后回位和快速连续挥拍；
- 建立轴旋转、采样率、幅值、时间伸缩、孤立冲击和周期运动的性质测试；
- 强度和预测球速始终作为训练估计值，并保留物理上限与质量门槛；
- 未来若获得真实球场标注，只在预先定义的指标上校准，不回写或挑选测试样本。
