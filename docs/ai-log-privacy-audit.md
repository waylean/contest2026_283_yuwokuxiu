# AI Coding 日志隐私与完整性审计

审计日期：2026-07-27

## 结论

本项目不直接提交开发者电脑中现存的两个 Codex Desktop 长会话。两个会话均为
跨项目、长周期对话，包含与参赛作品无关的工具输出和敏感上下文；手工删改后再
提交又会破坏官方日志的序号和完整性校验。因此采用以下合规路径：

1. 旧会话按完整会话排除，不复制原文、不生成删节版 JSONL。
2. 只在官方 openvela `.repo` 工作区内进行后续参赛开发。
3. 使用赛事官方采集器原生生成 `logs/<github-login>/` 内容。
4. 敏感信息只在采集写入前自动替换，不事后修改已经生成的 JSONL。

结构化开发摘要见 `docs/ai-native-development-log.md`。该文档是人工复核后的
研发索引，不替代官方机器采集日志。

## 排除依据

### 1. 内容边界不满足最小化原则

两个会话横跨商业版本、Android 应用、设备调试、发行支持和大赛版本，直接提交
会把大量与本次独立手环作品无关的信息带入公开仓库。

### 2. 存在敏感信息类别

审计发现的类别包括设备认证材料、访问令牌、邮箱、手机号、本机绝对路径、用户
截图上下文以及发行和支付相关信息。本仓库不记录任何真实值。

### 3. 当前格式不能由官方采集器可靠回放

赛事采集器 `1.2.0` 支持 Codex CLI 的 Stop Hook 输入，但其共享解析器读取
顶层 `message` 事件。Codex Desktop 的原始记录以
`response_item.payload` 包装消息和工具事件。直接回放会丢失主要内容，不能
作为完整日志提交。

### 4. 禁止伪造或事后改写

不把聊天摘要转换成看似由官方采集器生成的 JSONL，也不手工删除官方日志中的
单条事件。需要排除时按整个历史会话排除。

后续参赛会话必须满足：

- 一个会话只处理一个明确的参赛里程碑。
- 会话结束后先运行官方校验，再审查敏感类别和无关内容。
- 只提交完整、通过校验且与参赛作品直接相关的会话。
- 不提交 RPK、密钥、签名材料、用户原始数据或本机专用配置。

## 采集前脱敏

本机 staging 已配置自定义规则，并用虚构样本验证。规则覆盖：

- Xiaomi 或第三方访问令牌；
- AuthKey 标签后的认证值；
- 通用 token、API key、secret 和 signature 参数；
- 邮箱和中国大陆手机号；
- 本机用户目录；
- URL 中的认证、签名和来源查询参数。

虚构样本测试共生成 2 个事件，触发 7 次替换；全部原始虚构敏感值均未进入输出。
脱敏规则保存在本机 staging，不纳入仓库，避免暴露本机配置。
