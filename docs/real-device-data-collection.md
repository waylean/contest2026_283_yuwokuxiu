# 小米手环 10 Pro 真机数据采集流程

本流程只适用于 `tools/real-device-capture/` 中的独立诊断包
`com.waylean.bmtsmash.capture`。它不会替换、修改或向正式参赛包
`com.waylean.bmtsmash.contest` 增加权限。

## 1. 构建和安装

准备 openvela/AIoT 快应用工具链及小米手环 10 Pro 调试环境，然后执行：

```sh
npm --prefix tools/real-device-capture install
npm --prefix tools/real-device-capture run build
```

使用 AstroBox 或赛事提供的真机安装通道安装本地生成的诊断 RPK。不要把 RPK、
签名、密钥或 `sign/` 目录提交到仓库。安装前在 AstroBox 中核对包名必须是
`com.waylean.bmtsmash.capture`；若显示正式包名，立即停止安装。

不同版本 AstroBox 的安装入口名称可能不同，应选择“安装本地快应用”或等价入口。
诊断包声明加速度传感器、本地存储、路由和仅用于研发导出的
`system.interconnect`。正式参赛包不包含互联能力，训练过程也不依赖电脑。

电脑端还需构建并安装最小 AstroBox 采集插件：

```sh
cd tools/real-device-capture/astrobox-collector
cargo build --release --target wasm32-wasip2
python3 scripts/build_dist.py
```

插件只监听 `com.waylean.bmtsmash.capture` 的导出消息，不发送传感器控制命令。

## 2. 采集前检查

1. 手环电量充足，表带松紧保持不变，记录测试日期和固件版本到单独的测试报告；
   不要把设备序列号或账号写入采集数据。
2. 打开诊断工具，确认首页显示隐私说明和“新建匿名会话”。
3. 点击新建后，等待约 2 秒稳定基线；状态应显示 `game 20ms`。
4. 随时确认“停止采集”和“保存并退出”可见。若传感器报错，工具应进入
   “已安全停止”，退出按钮仍可用。

## 3. 六阶段测试

依次执行以下标签阶段。每个阶段先用 `- 次数` / `+ 次数` 设置预期次数，再点
“开始本阶段”；动作结束后点“结束本阶段”，然后进入下一阶段。

| 阶段 | 建议时长或次数 | 主要用途 |
| --- | ---: | --- |
| 静止 | 60 秒，预期 0 次 | 基线误判 |
| 步行 | 3 分钟，预期 0 次 | 周期运动误判 |
| 普通摆臂 | 20 次 | 非持拍大幅摆动误判 |
| 持拍回位 | 10 次 | 回位二次计数 |
| 过顶空挥 | 20 次 | 无击球挥拍检出 |
| 实际击球 | 20 次 | 实际场景检出 |

阶段开始、结束、预期次数及候选事件数均写入会话索引。动作次数应由测试者现场
计数；不要录制视频，也不要在工具中输入姓名、位置或账号。每次动作之间建议留出
至少 2 秒，便于形成独立候选窗口。

采集器在内存中只维护约 1 秒触发前环形缓冲，并只持久化候选事件的前后窗口。
每个已完成事件立即写为一块、每会话最多 120 块，不会保存 2–3 小时连续 50 Hz 原始流。
达到上限时会安全停止，应导出当前会话后再新建。

## 4. 停止和导出

1. 在仓库根目录运行一键接收命令。它会启动 AstroBox，并自动把标准输出保存到
   带时间戳的文件：

   ```sh
   npm run capture:listen
   ```

2. 在 AstroBox 中连接手环，打开 `BMT Capture Collector`，依次点击“刷新”和
   “注册”。界面必须显示“监听成功”。
3. 手环完成测试后先点“停止采集”，在第六阶段结束后点“生成导出索引”。
4. 手环显示“已导出”，插件的接收分片数持续增加，说明电脑已收到数据。
5. 关闭 AstroBox。一键脚本会自动恢复并校验数据，终端最后显示
   `Recovered capture: ...` 即为结果目录。

用户不需要抄写任何数值，也不需要读取快应用 KV。发送内容按不超过 700 字符的
数据段逐片传输，包含会话、种类、索引、分片序号、总片数、长度和 FNV-1a 校验。
断线或缺片时，原始 manifest/chunk 仍保留在手环 `system.storage`，重新注册插件
后再次点击导出即可；电脑端会容忍内容相同的重复分片。

## 5. 电脑端校验

一键接收命令会自动执行恢复。只有需要从旧日志重新恢复时，才手工运行：

```sh
npm run capture:recover -- \
  --input tools/real-device-capture/out/astrobox-capture.log \
  --out tools/real-device-capture/out/recovered
```

脚本先从乱序分片恢复原始 `manifest.json` 和 `chunks/*.json`，再生成
`capture.json` 与 `samples.csv`。工具校验：

- manifest 引用的分块是否齐全、索引和会话 ID 是否一致；
- FNV-1a 完整性校验值和事件数量；
- 阶段、事件及样本时间是否单调；
- 每个候选窗口的中位采样率是否接近 50 Hz；
- 窗口内掉采样缺口、重复序号和重叠窗口样本；
- 每个事件是否具有算法特征、接受/拒绝结果和原因。

命令退出码为 `0` 才表示无完整性错误。采样率、缺口或窗口重叠会作为警告保留在
输出 JSON 的 `validation.issues` 中，不应删除。CSV 保留事件到样本的对应关系；
JSON 的 `uniqueSamples` 同时提供按序号去重后的样本。

## 6. 把数据交给开发者

仅发送以下文件：

- 原始 `manifest.json`；
- 原始 `chunks/*.json`；
- 校验产生的 `capture.json` 和 `samples.csv`；
- 不含身份信息的测试说明，例如“右手、标准松紧、阶段实际完成次数、固件版本”。

压缩前再次检查文件中没有姓名、精确位置、设备序列号、密钥、账号、视频或其他
应用日志。通过团队批准的文件通道交付，并提供离线工具输出的校验结果。不要通过
公开 issue 上传真机采集包。

## 7. 掉电、异常和退出恢复

- 每个已完成候选会分块写入 `system.storage`，会话索引持续更新。
- 掉电或异常退出后重新打开诊断工具，选择“恢复未导出会话”。恢复会沿用匿名
  会话 ID、阶段记录、分块引用和样本序号；异常瞬间尚未完成的单个候选可能丢失。
- 若提示传感器或分块保存失败，先使用可见的“保存并退出”，不要反复启动传感器。
- 若导出失败，不要清除应用数据；重新连接并注册电脑采集插件后再次导出。
- 成功导出和电脑端校验前，不要卸载诊断包。确认交付后可通过系统卸载清除本地
  诊断数据。

## 8. 真机验收记录

每次固件或采集器版本变化后至少确认：

- 实测回调间隔和采样率报告；
- 六阶段开始/结束时间与现场次数对应；
- 接受和拒绝事件均含前后窗口、特征及原因；
- 后台、返回键、传感器失败、停止、退出和掉电恢复均不会黑屏锁死；
- AstroBox 或批准的手机通道能导出所有 manifest/chunk；
- 离线合并命令通过，警告已人工复核。

这些项目必须在真实小米手环 10 Pro 上确认；模拟器和仓库自动测试不能替代。
