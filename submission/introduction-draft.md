# BMT Smash 作品介绍初稿

> 本文件是评审文档的内容底稿。最终提交前需补充匿名产品证据、算法性质测试
> 图和架构图，并导出为 PDF 或 PPTX。

## 1. 一句话定位

BMT Smash 是一款运行于小米手环 10 Pro 的 openvela 独立羽毛球训练应用，
利用持拍手腕的三轴加速度，在不依赖手机、网络和云服务的情况下识别有效挥拍，
提供挥拍强度、预测球速、心率、历史记录和比分等现场反馈。

## 2. 目标用户与行业痛点

目标用户是希望量化训练、但无法持续使用雷达测速仪或高速摄影的普通羽毛球
爱好者。专业设备成本高、架设复杂，手机也不适合在对抗过程中持续操作；手环
则天然位于持拍手腕，具备低干扰、低门槛和长时间佩戴的优势。

本作品解决的不是“替代专业雷达”，而是让用户在每次训练中持续获得可比较的
腕部动作反馈。挥拍强度和预测球速均明确标注为训练估计值。

## 3. 核心体验

1. 用户设置持拍手、身高和表带松紧。
2. 在控制页开始、暂停、继续或结束训练。
3. 前台以高频三轴加速度采样构建候选动作窗口。
4. 算法过滤普通摆臂、跑动、碰撞和击球后回位。
5. 指标页显示实时波形、挥拍强度、次数、最大强度和预测球速。
6. 心率能力可用时提供当前、平均和最高心率；失败不会阻塞挥拍检测。
7. 结束训练后在本地保存摘要，支持冷启动恢复和历史回放。
8. 独立计分页减少比赛中操作手机的需求，并提供明确退出路径。

## 4. openvela 能力应用

| openvela 能力 | 作品中的用途 |
| --- | --- |
| Quick App 图形与交互 | 七页横向导航、实时波形、历史列表、计分和容错状态 |
| `system.sensor` | 获取前台三轴加速度 |
| `service.health` | 可选心率读取，独立故障隔离 |
| `system.storage` | 设置、训练快照和历史摘要持久化 |
| `system.brightness` | 训练期间保持界面可见 |
| `system.router` | 提供明确、可恢复的退出流程 |

作品以现有手环硬件为载体，不涉及新开发板、BSP 或驱动移植。核心能力全部在
手环端运行，Android 联动版不属于本次参赛基线。

## 5. 技术方案

数据流如下：

```text
加速度回调
  -> 重力与动态分量分离
  -> 静止噪声与采样间隔驱动的有界自适应阈值
  -> 候选事件窗口
  -> 峰值、jerk、冲量、持续时间、方向一致性
  -> 窄脉冲碰撞、普通摆臂和方向感知回位过滤
  -> 挥拍强度与预测球速
  -> 实时界面和本地训练历史
```

算法采用可解释的物理特征和质量门控。传感器回调专注采样和检测，实时图形按
80 ms 节流刷新，避免 20 ms 回调被界面更新阻塞。停止训练后到达的延迟回调会
在修改界面或存储前被丢弃，心率、亮屏和传感器能力分别清理，降低结束训练后
重启或黑屏风险。

`competitionSwingAlgorithm.js` 是唯一算法源。构建前由确定性脚本同步到
核心评分、估算和回位函数会自动同步进 Quick App 运行时代码，静态检查会拒绝
这些核心函数与规范源码不一致的提交。原始样本回放是确定性的预处理参考；实机
运行时额外包含不应期、真实回调间隔和周期运动状态，不把二者描述为逐样本等价。

## 6. 技术优化与能力拓展

- 使用 JSC 字节码构建，禁用已知会带来兼容风险的 protobuf 组合。
- 通过合成传感器回放验证误判、方向感知回位、强度单调性和物理上限。
- 通过性质测试验证坐标轴变化、幅值变化、20–30 ms 回调差异和单点冲击。
- 通过模拟器自动验证启动、训练、停止、退出和冷启动历史恢复。
- 将心率作为可选能力隔离，服务缺失或权限失败时保留主训练流程。
- 提供可复用 `openvela-wearable-swing` Skill，固化结构审计、独立运行边界和
  敏感信息检查。

## 7. AI-Native 开发流程

AI Coding 用于需求归纳、代码隔离、算法回归测试、模拟器调试、独立盲审和
提交材料整理。AI 生成的改动不直接视为完成，而是依次经过静态检查、算法
回放、性质测试、JSC 构建和模拟器生命周期验证。

仓库包含：

- `docs/ai-native-development-log.md`：结构化开发摘要；
- `logs/<github-login>/`：赛事官方采集器导出的对话记录；
- `skills/openvela-wearable-swing/`：本项目沉淀的可复用 Skill。

当前工具未提供精确 Token 用量，因此不估算、不虚构。最终文档只填写官方
采集器能够核实的数据。

## 8. 当前验证结果

- 从远端全新克隆后，依赖安装、代码审计、算法回放和 JSC-only 构建通过。
- 模拟器中控制页、指标页、心率页、结束后生命周期和冷启动历史恢复通过。
- 仓库不包含 RPK、APK、签名密钥、AuthKey、用户数据或本机绝对路径。

本次不使用非球场标签动作或 AstroBox 诊断链路证明实战准确率。合成数据只验证
坐标不变性、单调性、物理上限和误判门控等确定性性质，不会被描述为 precision
或 recall。未来只有在获得视频和人工复核标注、并冻结独立测试集后，才发布真实
准确率。

## 9. 创新点与产品价值

1. 将手环从通用健康终端扩展为持拍手腕上的专项训练工具。
2. 在资源受限的可穿戴端完成实时信号处理、容错、图形反馈和历史管理。
3. 用自适应门槛、窄脉冲冲击过滤和方向感知回位约束高峰值动作，避免仅凭一次
   加速度峰值夸大结果。
4. 以手机和网络完全不可用为设计前提，适合真实球场使用。
5. 已有超过 1,000 名付费用户的市场反馈，但最终材料必须补充来源、时间和
   匿名化证据后才作为正式结论。

## 10. openvela 改进建议

1. 为手表和手环提供统一、可检索的传感器能力矩阵与设备差异说明。
2. 为 Quick App 模拟器提供官方连续传感器 Mock 示例和生命周期测试模板。
3. 明确健康服务在不同产品、权限和运动状态下的错误码及降级策略。
4. 提供可穿戴安全区、圆屏和窄屏布局的官方预览与自动截图能力。

发现可复现问题后，将优先提交最小复现、文档修复或上游 PR，而不是只在作品
说明中提出笼统建议。

## 11. 限制与隐私

- 只有三轴加速度时无法完整恢复球拍空间姿态。
- 预测球速是训练估计，不是雷达测量结果。
- 心率仅作为运动参考，不用于医疗诊断。
- 所有训练摘要保存在手环本地；参赛数据只使用匿名样本。
