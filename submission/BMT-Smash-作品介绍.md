# BMT Smash 作品介绍

**队伍名称：** 羽我苦修  
**作品名称：** BMT Smash  
**作品方向：** 手表应用创新  
**目标设备：** 小米手环 10 Pro  
**技术基线：** openvela / Xiaomi Vela Quick App  

## 1. 一句话定位

BMT Smash 是一款运行于小米手环 10 Pro 的 openvela 独立羽毛球训练应用。它利用持拍手腕的三轴加速度，在不依赖手机、网络和云服务的情况下识别具有挥拍形态的动作，并提供挥拍强度、预测球速、心率、历史记录与比分等现场反馈。

## 2. 目标用户、应用场景与行业痛点

目标用户是希望量化训练、但无法持续使用雷达测速仪或高速摄影的普通羽毛球爱好者。专业设备成本高、架设复杂，手机也不适合在对抗过程中持续操作；手环天然位于持拍手腕，具备低干扰、低门槛和长时间佩戴的优势。

BMT Smash 不宣称替代专业雷达。挥拍强度和预测球速均明确定位为训练估计值，重点是让同一位用户在日常训练中持续获得可比较、可回看的反馈。

## 3. 核心体验

1. 用户设置持拍手、身高和表带松紧。
2. 在控制页开始、暂停、继续或结束训练。
3. 应用以前台高频三轴加速度采样构建候选动作窗口。
4. 算法过滤普通摆臂、跑动、窄脉冲碰撞和击球后回位。
5. 指标页显示实时波形、挥拍强度、有效次数、最大强度和预测球速。
6. 心率能力可用时提供当前、平均和最高心率；失败不会阻塞挥拍检测。
7. 结束训练后在本地保存摘要，支持冷启动恢复和历史回放。
8. 独立计分页减少比赛中操作手机的需求，并提供明确退出路径。

## 5. 算法与技术优化

处理链路如下：

```text
20 ms 级三轴加速度回调
  -> 重力与动态分量分离
  -> 静止噪声与回调间隔驱动的有界自适应阈值
  -> 候选事件窗口
  -> 峰值、jerk、冲量、持续时间、方向一致性
  -> 窄脉冲碰撞、普通摆臂和方向感知回位过滤
  -> 挥拍强度与预测球速
  -> 实时图形与本地训练历史
```

算法不是“单峰值即挥拍”。候选窗口同时检查峰值动态加速度、jerk、平方积分、冲量、突发比、峰值位置、半高宽、方向一致性和周期运动状态。窄脉冲门控用于拒绝碰撞，方向只作为回位判断的辅助证据，避免将强度接近的反向连续挥拍直接过滤。

为保证资源受限设备上的稳定性，传感器回调专注采样和检测，实时图形按 80 ms 节流刷新。停止训练后到达的延迟回调在触碰界面或存储前被丢弃；传感器、心率和亮屏能力分别清理，降低结束训练后的重启和黑屏风险。

`competitionSwingAlgorithm.js` 是唯一算法源。构建前由确定性脚本同步到 Quick App 运行时代码，静态检查会拒绝核心评分、估算和回位函数与规范源码不一致的提交。

## 6. 验证方法与证据边界

项目包含可重复的确定性回放与性质测试，用于验证：

- 坐标轴置换与符号变化不改变检出结果；
- 动态幅值增强时强度保持单调且不越过物理上限；
- 20–30 ms 回调差异处于预设容差；
- 30–70 m/s² 单脉冲和窄双脉冲不会被计为挥拍；
- 快速同方向连续动作不会仅因时间接近被判为回位；
- 较弱反向动作优先判为击球后回位；
- 普通摆臂、跑动和静止夹具不产生有效挥拍。

合成回放验证的是算法性质，不代表真实球场 precision 或 recall。只有在获得视频、击球类型和人工复核标注并冻结独立测试集后，项目才会发布真实准确率。

## 7. AI-Native 开发工作流

参赛版本的重构、算法测试、文档和演示材料阶段，AI 参与约 90% 的代码与文档草拟；人工负责 100% 的需求定义、产品取舍、真机体验、风险边界和最终验收。该比例是开发工作量估算，不是逐行著作权归因。

使用的 AI 与工程工具包括：

- OpenAI Codex：需求拆解、代码实现、测试、构建和材料整理；
- K3 前端设计委派：界面与演示画面视觉实现；
- HyperFrames：两分钟演示视频的可复现合成与渲染；
- 多智能体盲审：分别检查运行时/算法风险和可穿戴体验/赛事合规；
- 自研 Skill `openvela-wearable-swing`：固化项目审计、独立运行边界和敏感信息检查；
- GitHub CLI、浏览器和本地构建工具：PR、CLA、模拟器和提交状态核验。

赛事官方采集器中提供 Token 字段的三份完整会话合计 **1,013,785 Token**。该数字不包含未由官方采集器记录的历史桌面会话。AI 生成内容必须依次通过静态检查、算法回放、性质测试、JSC 构建、模拟器生命周期验证和人工审阅，不能以“生成完成”代替验收。

## 8. 创新功能与体验亮点

1. 将通用健康手环扩展为持拍手腕上的专项训练工具。
2. 在资源受限的可穿戴端完成实时信号处理、容错、图形反馈和历史管理。
3. 使用有界自适应门槛、窄脉冲过滤和方向感知回位约束高峰值动作，避免随手一甩就获得夸张结果。
4. 以手机和网络完全不可用为设计前提，适合真实球场使用。
5. 结束并非数据终点：训练摘要保存在本地，支持历史回放和冷启动恢复。
6. 截至本材料整理时，项目商业版本在爱发电已有超过 1,000 名付费用户；这一数据用于说明真实需求，不作为算法准确率证据。

## 9. 新硬件适配与驱动开发

本次作品不涉及全新硬件、开发板、BSP 或驱动开发，因此该项不适用。项目使用小米手环 10 Pro 已提供的传感器、健康、图形、存储、亮屏和路由能力，通过应用层算法、生命周期隔离和能力降级完成创新。

## 10. 对 openvela 的使用建议

1. 为手表和手环提供统一、可检索的传感器能力矩阵与设备差异说明。
2. 为 Quick App 模拟器提供官方连续传感器 Mock 示例和生命周期测试模板。
3. 明确健康服务在不同产品、权限和运动状态下的错误码与降级策略。
4. 提供可穿戴安全区、圆屏和窄屏布局的官方预览与自动截图能力。
5. 为高频传感器应用提供统一的性能预算、前后台限制和数据节流指南。

## 11. 限制与隐私

- 只有三轴加速度时无法完整恢复球拍空间姿态。
- 预测球速是训练估计，不是雷达测量结果。
- 心率仅作为运动参考，不用于医疗诊断。
- 训练摘要保存在手环本地；项目不上传用户身份、健康记录或设备凭据。
- 提交包不包含 RPK、APK、签名密钥、AuthKey 或真实用户原始数据。
